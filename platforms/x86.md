# x86_64 mini PC (Nipogi AK2PLUS, Intel N100)

What an x86 mini PC needs to play an MPF + Godot game with PinUP videos on two screens, hardware decoding included.
Status 2026-10-26: **nothing measured yet** on the machine (not connected to any session); everything here is from the
product pages and the code. Fill the "Measured" table with [eval_hw.sh](x86/eval_hw.sh) and the game.

## The machine

| | Nipogi AK2PLUS ([TechRadar](https://www.techradar.com/pro/nipogi-ak2-plus-mini-pc-review), [Notebookcheck](https://www.notebookcheck.net/NiPoGi-AK2-PLUS-debuts-with-scalable-specs.767511.0.html)) |
|---|---|
| CPU | Intel N100 (Alder Lake-N), 4 cores / 4 threads, 6 W |
| GPU | Intel UHD Graphics, 24 EU (Xe-LP): its media engine decodes H.264, HEVC (8 and 10 bit), VP9 and AV1 in hardware (VAAPI / Quick Sync, driver `iHD`) |
| Memory / disk | 16 GB DDR4 single channel (the GPU shares it), 512 GB M.2 SATA (under the board), one free 2.5" SATA bay |
| Video / audio | 2 x HDMI 2.0 (two screens), one jack; HDMI sound |
| Network / USB | 1 GbE, Wi-Fi 5, Bluetooth 4.2; 2 x USB 3.2 Gen 1, 2 x USB 2.0 |
| Cooling | the reviews mention no fan; 30 W supply |

## What is done

- GoZen with VAAPI for Linux x86_64: [fixes/gde-gozen/hwdec-vaapi-linux-x86.md](../fixes/gde-gozen/hwdec-vaapi-linux-x86.md).
  Loads and falls back to software without a GPU (Godot 4.6.3, headless); the GPU path is untested.
- The Linux installer installs `libva2` and `libva-drm2` on x86_64 (the library is linked to them); a Debian/Ubuntu box also needs the driver:
  `sudo apt install intel-media-va-driver vainfo` (Intel) or `mesa-va-drivers` (AMD).
- The minimal image: [x86/image/README.md](x86/image/README.md).
- The setup page replaces an installed game's GoZen for any architecture now (it was arm64 only), and keeps the bundle's own when its
  `bundle.json` lists `vaapi` in `gozen`.

## Testing without a keyboard

- Keys: XTest key presses (`1` start, `5` coin) reach the game even when its window is hidden.
- BCP: MPF's server on `127.0.0.1:5051` takes switch commands, e.g. `switch?name=s_start_button&state=1` (a plain TCP line), which starts a game with no keyboard.
- From another computer, tunnel both ports: `ssh -L 8080:localhost:8080 -L 5051:localhost:5051 mpf@<ip>` (the setup page and BCP, nothing is opened on the network).

## Service

`mpf-game.service` uses `Restart=always`: a game that exits cleanly (the X session restarted, an update became active) comes back by itself; `on-failure` would leave the screen black.
